# 多房间版本部署与使用

## 首次配置

本版本使用新的 `data/multi-rooms.sqlite`，不会读取或迁移旧版 `queue-data.json`，旧文件可保留

将 `config/application.properties.example` 复制为 `config/application.properties`，直接编辑下面的必填项

```properties
app.rooms.root-key=你的最高许可密钥
```

最高许可必须为 8–16 位 ASCII 可见字符，可使用大小写英文字母、数字及符号，不含空白，示例中的中文占位文字必须替换

配置文件遵循 Java properties 转义规则，密钥中每个反斜杠需要写成 `\\`，转义后的实际密钥仍需满足 8–16 位限制

未配置或格式错误时，服务拒绝启动，最高许可只能在这个服务端文件中更换，更换后重启服务，网页不提供更换入口

`app.music-api.base-url` 应配置为实际对外访问地址，Docker 的网易云接口地址为 `http://netease-api:3000`，Windows 启动器使用 `http://127.0.0.1:3000`

## Docker

在仓库根目录运行

```sh
cp config/application.properties.example config/application.properties
# 编辑最高许可和对外访问地址后启动
docker compose up -d --build
```

默认页面地址为 `http://服务器IP:8848`，Compose 挂载的三个目录分别保存服务配置与普通许可、音频缓存、SQLite 数据

## Windows 启动器

启动器运行目录是 EXE 所在目录，首次启动会生成 `config/application.properties` 空模板

直接编辑该文件的最高许可后再启动服务，启动器设置页面只说明文件位置，不接受输入或修改最高许可，也不再传入全服 Cookie

发布流程随包提供 Node.js 22 和 NCM API 源码运行时，替代原先的 Node.js 18 打包运行时，Java 21、FFmpeg 继续随包提供

本地源码构建需要 Git 2.x、Node.js 22.12.0 或以上、JDK 21、Go 1.23.12 或以上的稳定版、Wails 2.12.0，以及 Windows x64 静态 FFmpeg 7.0.1 或以上。Maven 由仓库 Wrapper 提供；完整工具准备和排错见 [构建说明](../BUILD.md)。可运行

```powershell
.\build-windows.ps1 -NeteaseApiPath '..\api-enhanced' -FfmpegPath 'C:\tools\ffmpeg.exe'
```

`NeteaseApiPath` 指向预先检出的 `NeteaseCloudMusicApiEnhanced/api-enhanced`，最终交付输出为 `dist/windows/MusicParty-windows-<版本号>-<提交号>.exe`。版本号只读取仓库根 `VERSION`（初始为 `1.3.9`），提交号为当前 Git `HEAD` 的短提交号；调整发布版本只修改根 `VERSION` 并提交后构建。

## 许可清单与管理入口

访问根地址始终显示 `SECURITY ACCESS`，点击 `JOIN ROOM` 右侧的锁图标打开许可验证，成功后直接打开 `ROOM MANAGER`，普通许可管理自己的房间，最高许可管理所有房间、普通许可清单和全局系统参数

每个许可最多创建 9 个自己的房间，最高许可也适用，房间名允许重名，实际操作始终使用 8 位房间 ID

普通清单保存在 `config/licenses.json`，首次自动创建空清单，也可停服后手动编辑

```json
[
  { "id": "LICENSE-A", "key": "ReplaceMe9", "note": "示例许可🎵" },
  { "id": "LICENSE-B", "key": "ReplaceMe8" }
]
```

ID 为 1–64 位英文字母、数字、下划线或连字符，须唯一且不能为 `ROOT`，密钥遵循与最高许可相同的格式规则，所有密钥必须互不相同

手动替换密钥时保留原 ID，所属房间跟随该 ID 保留，删除清单中的 ID 会在下次启动时删除其全部房间

运行中使用网页 `UPDATE` 和 `DEL` 会立即生效，旧管理会话失效，删除许可同时删除所属房间及缓存，管理会话默认有效 12 小时

最高许可可编辑普通许可的备注，最多 16 个可见字符，支持中文和组合 emoji，也可留空，替换密钥保留备注，编辑备注不撤销已有会话

普通密钥在最高许可的清单中默认遮掩，点击眼睛回显，关闭窗口后重新遮掩，普通许可无权获取该清单，最高密钥不会回显

## 全局系统参数

最高许可的 `ROOM MANAGER` 在“全部房间 / 我的房间 / 许可清单”后提供“系统参数”页面，以下九项统一应用于所有房间，普通房主无法单独修改

| 设置 | 范围 |
|---|---|
| 队列最大长度 | 1–10000 |
| 历史记录容量 | 0–10000 |
| 用户点歌上限 | 1–10000 |
| 导入单次上限 | 1–10000 |
| 聊天记录容量 | 0–100000 |
| 发言频率限制（毫秒） | 0–600000 |
| 消息最大长度 | 1–10000 |
| B站时长上限（分钟） | 1–1440 |
| 配对码更新周期（分钟） | 1–60 整数，默认 10 |

保存后立即生效，无需重启，已使用的房间、暂未使用的房间及新房间共用同一组参数，配置独立保存在 SQLite，重启后继续恢复

首次使用全局参数时，从服务端 `app.music-api` 的对应参数初始化，旧房间保存的这九项值不再生效，全局参数保存后不会被启动默认值覆盖

修改配对码更新周期后，立即更新所有房间（包括暂未使用的房间）的配对码，并从保存时刻重新计时，重启后保留计时锚点。“一起看”为禁用的占位输入框，不保存任何配置。

降低队列或用户点歌上限会限制后续加入，保留已有队列，降低历史记录或聊天记录容量会裁剪旧记录，容量为 0 时不保留相应历史

解析音质上限仍由房主在“管理终端 → 播放核心”中设置，位于直播推流下方、进度条跳转权限上方，选择后立即保存，仅作用于当前房间

## 房间与凭据

加入房间后，浏览器地址使用 `/<房间ID>`，例如 `https://musicparty.com/M9vkDrTt`。公开房间地址允许直接进入 CONNECT，首次访问没有保存昵称时可先以游客收听。私有房间地址显示 `NEED CODE`，输入该房间的配对码、所属许可或最高许可后进入，使用许可会取得对应管理权限。部署在反向代理后时，房间地址应转发到本应用，由应用返回网页入口。

管理终端的配对码卡片显示 `PAIRING CODE / UPTIME / OPEN / SHOW`。Owner/Root 通过 OPEN 设置 public/private，默认 private，public 仍允许配对码加入。SHOW 独立控制播放页配对码展示，默认关闭，`//code on/off` 操作 SHOW，不改变房间开放状态。

普通成员在房间内执行 `//admin`，首次成功验证所属许可或最高许可后，当前连接升级为 Owner/Root，后续使用有效管理会话，无需重复输入许可密钥。许可更新、删除或管理会话失效后需重新验证。

新房间为空队列、暂停播放、未配置 Cookie，首次点击 `CONNECT` 成功后自动打开一次管理台，播放界面沿用原项目

进度条跳转默认禁止，管理员可设置“禁止跳转 / 仅管理和点歌者 / 全部允许”，沿用原项目的游客限制，房间共用三秒冷却，切歌清除冷却，跳转保持播放或暂停状态

网易云歌曲有副歌数据时显示副歌起点标记，没有数据或接口不可用时正常播放，原点赞标记保留

音量采用两条线性滑杆，第一条 0%–100%，滑满时显示下方 100%–200%，可直接输入数字，100% 对应原线性音量的 50%，200% 对应原最大输出，旧记忆保持实际输出，首次使用仍显示 10%

网易云优先使用 `获取 Cookie` 二维码登录，也可手动更新，B站手动更新 Cookie，凭据与房间配置保存在 SQLite，仅当前房间生效

配对码为 4 位数字，包含前导零，初始默认每十分钟统一更新；ROOT 可将周期改为 1–60 整数分钟，修改时立即刷新全部房间并重新开始倒计时，旧码 30 分钟内不再使用

访问同一房间地址时，同一周期刷新、关闭再开、重连可复用有效入房凭据，服务重启也可恢复周期内的入房凭据。码更新后，私有房间重新连接需要新码或有效管理许可，公开房间可直接重新进入，保持连接的成员继续使用。访问根地址仍显示 SECURITY ACCESS，不自动恢复上次房间。

最后一个网页或 Android 成员离开后保留 10 秒重连缓冲，到期暂停播放并停止转码、断开直播收听连接，之后重新加入保持暂停，由成员手动播放

昵称和平台绑定为同一用户身份共享，队列、聊天、播放进度、音质等播放设置与 Cookie 按房间隔离，九项系统参数全局共享，可以同时打开多个房间

Android 返回键先关闭弹窗，再返回房间入口，继续返回可切换服务器，离开房间时锁屏媒体状态同步为暂停

## 备份、恢复与资源

停止服务后一起备份 `config/application.properties`、`config/licenses.json`、`data/multi-rooms.sqlite` 及同名 `-wal`、`-shm` 文件，如果存在，同时可备份 `cached_media/rooms`

恢复时使用同一套配置、清单与数据库，启动时重新核对许可归属和配对码周期，所有房间保持暂停

持久化沿用原项目的待播队列、历史和聊天记录，并保存房间设置及 Cookie，服务重启不恢复当前曲目的临时音频直链和运行中播放进度

99 个总房间、9 个同时使用、每房间 9 人为容量目标，服务不据此拒绝创建或加入，只保留每个许可的 9 个自建房间额度

全服默认同时下载 3 个任务、同时转码 12 个直播，超出后排队，每房间仍按原项目顺序处理下载，以下配置只限制资源工作并发，不限制房间或成员数

```properties
app.rooms.max-concurrent-downloads=3
app.rooms.max-concurrent-transcoders=12
```

缓存保留按房间计量的原有 `app.music-api.cache.max-size` 设置，部署时根据磁盘和带宽调整，新房间的房间级设置按服务端默认参数初始化，已有房间的网页设置不会被这些默认值覆盖，九项系统参数以全局保存值为准
