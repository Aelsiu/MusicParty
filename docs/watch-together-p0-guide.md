# 一起看视频（P0）使用说明

本说明只介绍新增的视频功能。当前支持房间 Bilibili Cookie、普通公开投稿的第一 P、完整单段 MP4、各成员浏览器直连 B站 CDN。真实 HTTPS、跨网络和手机验收尚待补测，详见 [验证记录](watch-together-vt00.md)。本地入口、启动与停止见 [本地试用](watch-together-trial.md)。

## 1. 准备和更新房间 Cookie

使用你自己的 B站登录账户，在桌面 Chrome / Edge 打开 `https://www.bilibili.com` 并登录。按 F12 打开开发者工具，进入 Network / 网络，刷新页面，选择发往 `www.bilibili.com` 或 `api.bilibili.com` 的请求，在 Request Headers / 请求标头中复制 **Cookie** 的完整值。

复制的是 `名称=值; 名称=值` 的一行请求头，不是响应的 Set-Cookie，也不是带 `Cookie:` 前缀的文本。完整登录 Cookie 通常包含 `SESSDATA`、`bili_jct`、`DedeUserID`，以及 `buvid3`、`buvid4`、`_uuid` 等设备字段；不要只复制一个 SESSDATA。不要删改、解码或重新编码字段值。

Owner / Root 进入目标房间，打开管理台的「平台凭据 / Credentials」，找到「手动更新B站Cookie」，粘贴完整值并点「更新」。Cookie 按房间保存；另一个房间需要单独配置。不要把 Cookie 发到聊天、截图、仓库或验证记录。

「本房间已配置 Cookie」只表示已经保存非空凭据，不能证明登录仍有效。未配置时视频区明确提示「房间尚未配置 B站 Cookie」，入队会失败。明确登录失效、凭据错误或风控会显示错误通知；重新登录 B站、重新复制完整 Cookie 并更新后重试。412、429、网络超时也可能与网络或风控有关，不能一律当作 Cookie 失效。

Cookie 更新后，后续解析使用新凭据，已播放的当前视频不会被强制中断。Cookie 不下发到成员浏览器；临时媒体地址会发送给房间成员用于直连。

## 2. 从听歌切到看视频，或切回

使用有效 Owner / Root 许可，并填写用户 ID 后进入房间。房间导航栏的「一起听歌 ⇄」按钮可切到视频；视频中「一起看视频 ⇄」可切回音乐。普通成员和游客只能看到模式标识。

点击后确认切换。原模式会暂停并保留当前媒体、进度、点播者、队列、播放模式、操作锁和投票现场；目标模式也保持暂停，需要手动点击房间播放按钮。两套队列互不混用。确认期间房间状态改变时，旧确认会取消，重新操作即可。

解析途中切换也保留待播项，返回后手动播放会先重试它。看视频期间音乐现场不会被音乐的 20 分钟闲置清理删除。最后一名成员离开后有 10 秒重连宽限，到期全房间暂停；重新进入不会自动恢复全房间播放。

进程重启只恢复模式、两边队列、历史和设置，两边均暂停；已起播媒体和播放进度不恢复。尚未起播的队列待播项恢复到所属队列首部。

视频模式保留音乐 FM / DJ 与直播配置，但不执行电台托管或转码。视频中不能开启或修改 FM / DJ 配置、开启音乐直播或获取可用直播链接；可以关闭。切回音乐后仍须手动播放。

## 3. 点播视频

切到视频后打开搜索。只显示 B站来源，支持以下入口：

- 在输入框输入 `BV1GJ411x7h7`、`BV1GJ411x7h7:p1`，或普通 `https://www.bilibili.com/video/BV1GJ411x7h7` 页面链接。
- 输入关键词搜索 B站视频，点击候选的入队按钮。
- 使用原有 B站账号绑定和收藏夹查询，点播收藏夹单条、选中项或全部导入。绑定仍属于 B站账号。

入队前，服务端会读取视频第一 P 的真实时长和 CID。搜索和收藏夹中的聚合时长仅供参考，不代表第一 P 时长。批量导入逐项校验，会通知成功、跳过数量和原因；沿用队列、单人和批量导入数量上限。

视频默认最长 120 分钟。Root 可在 ROOM MANAGER 的「系统参数」设置「视频时长上限」，范围 1–1440 分钟，全局生效；音乐原有 B站时长上限仍独立保留。

P0 明确拒绝 P2 及后续分 P（包括链接 `?p=2`）、AV、短链接、任意 CDN 地址、超过上限的第一 P。不支持会员、付费、番剧、区域限制、B站直播、多段流、DASH、分 P 选择或多画质选择。`qn=32` 是解析偏好，实际返回画质可能更低，以播放信息为准。

入队不会使已暂停房间自动起播。点好后点击底部房间播放按钮。

## 4. 房间控制和本端开始观看

底部播放 / 暂停、下一条、播放模式和进度条控制全房间；视频元素不显示原生控制条，速度固定为 1 倍。

- 已命名成员可以按房间现有权限播放、暂停、下一条和切换顺序 / 随机 / 单条循环；游客只观看。
- 管理台操作锁分别作用于当前模式。暂停锁阻止成员将正在播放的房间暂停，暂停后的房间仍可恢复播放。
- 开启投票切换时，点播者可以直接跳过自己的视频；其他成员须满足等待时间，再按有效在线成员比例投票。管理台强制下一条保留原有管理权限。
- seek 使用共享的进度权限：禁止、Owner / Root 与点播者、所有成员。合法 seek 后有房间级 3 秒冷却。
- 队列置顶、移除、个人清理和管理清理作用于当前模式；普通成员只能移除自己的队列项，管理者可以移除其他成员的项。重置当前模式不会清掉另一模式。
- 视频不提供点赞或歌曲下载；视频 like 指令会明确拒绝。

浏览器拦截自动播放时，视频上显示「点击开始观看 / 恢复观看」。点击只解锁本端，不会暂停或启动其他成员；房间暂停时，本端按钮不会绕过房间暂停。系统导致本端暂停、切到后台或缓冲时也不会反向发送全房间暂停。

音量使用本端设置。视频模式暂时禁用精简模式，切回音乐后恢复原来的精简偏好。点击「展开」可扩大视频和自定义控制区域；支持时桌面浏览器使用 Fullscreen API，失败时采用页面内展开。Android 壳采用页面内展开，P0 不承诺 iOS 原生全屏、画中画或视频锁屏控制。

## 5. 刷新视频源和处理失败

视频区右上角「刷新视频源」用于重新解析当前视频，不是切下一条。多端同时请求会合并，最短间隔 5 秒；暂时失败退避至 5 / 10 / 20 / 40 / 60 秒，界面显示可重试倒计时。

换源保留当前播放实例、房间进度和暂停状态。暂停较久后恢复时，服务端必要时先取新源，再开始房间计时。正在播放的单端网络错误会尝试刷新一次；其他成员继续播放。编码不支持或自动播放被拒属于本端问题，不无限请求服务端解析。

初次解析失败会保留待播项并保持暂停，不自动跳过。若还没有当前视频，顶部刷新按钮不可用：等待冷却结束，更新 Cookie 或网络后重新点击房间播放以重试待播项；也可移除它或点下一条。已存在当前视频时，可以手动刷新源。重复失败可更换浏览器或选择支持的普通公开视频。

刷新页面和重新连接只同步当前状态，不会无条件重新取流。源自然过期不删除现场。服务端不缓存、代理或转码视频；每个成员自行从 B站 CDN 获取媒体，播放是否可用仍受其网络、浏览器和 B站来源策略影响。

同步误差不超过 1.5 秒是待真实多端验收的目标，当前模拟测试和同机协议测试不代表已达标。
