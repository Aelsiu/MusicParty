# 多房间版本：页面设计与实施清单

状态：已按确认原型实施，多房间业务与网页已接入，Windows 和 Android 已完成编译验证，实机和真实账号验收范围见第 10 节。分支：`multi-rooms-ver`。日期：2026-09-30。

## 1. 已确认的范围

- Docker 服务器、Windows 启动器、浏览器及 Android 同步支持。
- 从空数据开始，不迁移单房间版本的数据。开发和交付过程不自动删除旧文件。
- 99 个总房间、9 个同时使用、每房间 9 人是容量目标，不是硬限制。
- 普通许可和最高许可自己创建的房间均最多 9 个。最高许可管理别人房间不占自己的额度。
- 房间 ID 是 8 位大小写英文字母和数字，服务端安全随机生成并检查唯一性。
- 房间名按扩展字素簇（用户看到的字符）计数，2–16 个；允许完全重名。支持中文和 emoji，禁止纯空白、换行及不可见控制字符；保留合法组合 emoji 所需字符。
- 密钥 8–16 位大小写英文字母、数字或符号，不含空白，不重复；支持手动输入及安全随机生成，随机默认 16 位。
- 最高密钥仅通过服务端配置文件修改，重启后生效；缺失或为空时拒绝启动。
- 普通许可可在清单中手动配置，也可由最高许可在网页新增、替换、删除。
- 替换普通密钥保留其房间和数据，旧密钥、旧管理会话失效。删除普通许可则彻底删除其全部房间。
- 网易云使用 NCM 二维码接口获取 Cookie，保留手动配置。B站继续手动配置。

## 2. 风格与组件规则

复用当前 `style.css` / Tailwind 的主题系统：medical、accent、surface、strong、overlay。新页面支持经典、蓝色、绿色、夜间、自定义主题，不能以固定颜色替代主题变量。

- 面板保持直线结构、1px 边框、右下或左上切角、竖向装饰条。
- 英文标题和状态保持现有等宽字体及大写风格；中文说明使用现有中文无衬线字体。
- JOIN ROOM 和 CREATE ROOM 为主题色主操作；管理与普通操作沿用 strong 色板，MANAGE 展开和悬停时背景及边框均保持 strong 色，DEL 文字使用主题 accent 色，结构参照现有 UNLINK。
- 图标沿用 Lucide；锁、解锁、关闭、复制、二维码等均配合可访问名称。
- 弹窗沿用现有模糊遮罩及淡入缩放，避免多层 Toast 被遮罩盖住；表单错误显示在对应表单内。
- 手机操作目标不小于约 44px，长名称换行，房间 ID 保持完整可读；键盘弹出不遮挡提交按钮。
- 尊重减少动画偏好；删除反馈不能仅依赖颜色或抖动。
- 播放界面直接复用现有 MainLayout、CenterConsole、PlayerControl、AudioEngine、队列、聊天、搜索、设置及视觉效果，仅增加房间上下文、必要身份/连接处理和入口导航，不以演示里的简化播放器替换现有界面。
- 所有界面内的 tips / 辅助说明不使用中文分号或句号，使用逗号或分行准确断句，表单校验和状态提示同样遵守。

## 3. 页面与状态

### SECURITY ACCESS

访问根地址始终显示 SECURITY ACCESS，不自动恢复上次房间。保留用户 ID 输入，配对码区域标题改为“输入配对码”，使用四格数字输入（含前导零），JOIN ROOM 使用主题色。锁按钮可直接点击，与 JOIN 同高、正方形。

点击 JOIN ROOM 右侧的锁图标打开许可验证弹窗，验证成功后直接打开 ROOM MANAGER。有效管理会话下按钮变为开锁并打开管理列表；支持悬停的设备展开显示 MANAGE 并压缩 JOIN，无悬停设备立即显示 MANAGE，展开时保持原有 strong 背景及边框颜色。

进入管理列表无需填写配对码；用户 ID 在实际入房时校验。没有房间时普通入口显示无可加入房间状态，不恢复原来“任何人首次创建”的入口。

状态：加载、服务不可达、许可验证中/失败/限流、配对码无效或已更新、昵称无效。请求中禁止重复提交。

### 房间地址 / NEED CODE

加入后浏览器地址为 `/<房间ID>`，例如 `https://musicparty.com/M9vkDrTt`。直接访问 public 房间进入现有 CONNECT 页面，首次访问没有保存用户 ID 时允许游客进入，后续操作仍沿用原有昵称要求。直接访问 private 房间显示 NEED CODE，复用当前主题、输入及弹窗组件，接受该房间的配对码或所属许可，最高许可也可进入。

同一房间地址可以恢复当前配对码周期内的有效入房凭据；根地址仍展示 SECURITY ACCESS。输入其他房间配对码不能进入地址指定的私有房间。许可验证通过后获得 Owner/Root 身份，只允许所属房间或最高许可进入。浏览器前进、后退及 RETURN 同步房间上下文，切换时清理旧音频和连接，过期异步请求不能重新进入旧房间。

### ROOM MANAGER

普通许可显示所属房间，顶部显示自己已使用额度 `n / 9`。列表每行包含可点击的房间名、完整房间 ID 和 DEL。允许重名，所有请求以 ID 操作。

最高许可可切换“全部房间 / 我的房间 / 许可清单”；全部房间额外显示所属许可标识，不显示密钥原文。创建房间始终归属当前最高许可自身，额度仍为 9。

DEL 必须三秒内对同一房间点击三次。前两次抖动并显示次数，第三次发起删除。超时、关闭、切换视图清零；不同房间不累计。提交期间禁用该行重复操作。

状态：空列表、额度已满、加载失败、删除提交中、删除成功、权限撤销、列表中的房间被其他管理会话删除。

### CREATE ROOM / CONNECT

创建弹窗显示字素计数，允许任何合规重名。输入法组合输入结束前不触发 Enter 提交，状态同步和提示刷新不能清空输入草稿，合法 ZWJ 组合 emoji 保留；单个 emoji 仍计一个字符，至少需要两个可见字符。创建前和服务端提交时均检查额度；创建请求具备幂等性。

成功后进入现有 CONNECT 版式，展示房间名、房间 ID。点击 CONNECT 前校验当前资格；连接失败不误显示已连接。新房间最初暂停、无队列、无 Cookie。

返回入口使用 `RETURN` 文字按钮，紧贴 CONNECT 按钮下方居中，与 `SYSTEM READY` 使用相同等宽字体、字号、字重和字距，不增加按钮背景或边框。

独立原型中的简化播放页仅用于演示连接流程，没有加载项目真实播放组件，不代表正式版本的播放器设计。正式实现直接复用原有播放页面及功能，仅增加房间适配与必要的新功能。

新建房间首次真正连接成功后自动打开管理台一次；普通加入、后续刷新/重连不再自动打开。

### ROOM ADMIN

凭据区域统一使用“手动更新网易云 Cookie”和“手动更新B站Cookie”标签，BILIBILI 标题旁不再单列“手动配置”。

复用现有管理员面板，明确显示房间名和 ID。MANAGE 已验证的会话无需再次输入密钥；普通入房用户输入 //admin 后首次必须使用该房间所属密钥，最高密钥可管理任何房间，验证成功后当前连接升级为 Owner/Root，后续复用有效管理资格。服务端同步升级连接权限，不能仅改变前端按钮状态。

- 原“修改房间密码”区域改为当前四位配对码、下一次更新时间、Steam 令牌式倒计时及复制。
- 配对码卡片为 `PAIRING CODE / UPTIME / OPEN / SHOW` 四栏，OPEN 为 public/private 滑动开关，SHOW 独立控制播放页配对码展示，两者默认关闭。`//code on/off` 继续控制 SHOW，public 仍可通过配对码加入。SHOW 关闭时普通成员接口和广播不包含配对码。
- 保留房间级播放控制、锁定、音质、私人 FM/DJ、直播和数据清理，队列/聊天及 B站时长等八项参数由 ROOT 全局设置，无音乐或暂停均不踢出在线成员。
- 原“全系统重置”改为明确的“重置本房间”，不得影响其他房间；具体重置内容需要可见说明。
- 页脚只显示已验证身份或许可标识，不声称未经实现的加密协议、不将原文密钥片段称为哈希。

### NETEASE LOGIN

“获取 Cookie”打开当前房间的登录区域：等待扫码 → 已扫码待确认 → 验证并保存 → 成功；另有取消、过期重试、失败重试。

登录任务绑定房间 ID、许可身份和会话版本；房间删除、许可替换/删除后任务不可再写入。验证成功并持久化后替换旧 Cookie，不把完整 Cookie 广播给客户端或写入日志。

二维码到期、任务超时、用户关闭等状态明确；保留手动输入作为备用。手机同设备完成网易云登录的可行跳转需在实机验证，不能承诺尚未验证的深链接。

### LICENSE MANAGER

仅最高许可可见。清单展示稳定许可 ID、关联房间数，替换按钮显示 UPDATE，删除按钮统一显示 DEL，DEL 文字使用主题 accent 色，密钥不回显。

新增/替换弹窗采用密码输入，支持显示/隐藏及随机生成；8–16 位、无空白、不得重复。替换提示使用“所属房间保留，旧密钥和旧管理会话立即失效”，不添加分号或句号。删除明确展示关联房间数量和一并删除的结果，再提交确认。

最高许可只显示“服务端配置”，不提供编辑/删除按钮。网页随机生成用于普通许可；最高密钥可通过离线工具生成后手动配置。

### 房间内导航及跨端

提供返回入口操作，退出时清理当前标签页音频、连接、队列/聊天视图和权限上下文。个人昵称、平台账号 ID 绑定及主题共用，房间状态独立。

Android 返回键优先关闭弹窗，再返回入口；切换服务器时撤销旧连接。后台与锁屏控制只操作当前有效房间，房间删除或连接资格失效时不能继续控制旧房间。

## 4. 配对码、在线与播放

- 每小时 00/10/20/30/40/50 分全服同步更新。当前有效码全局唯一，包含 0000。
- 旧码退出使用后至少 30 分钟不得重新分配，包括删除房间后释放的码。更新批次原子发布，不允许新旧映射部分混用。
- 按服务端时间及周期编号判定，而不是只比较数字；即便以后生成相同数字，旧资格也不可恢复。
- 通过同一房间地址访问时，配对码周期内刷新、关闭再开、重连可复用有效入房凭据；自然更新后私有房间再次连接须新码或有效管理许可，公开房间可直接重新进入。一直保持连接的用户不受影响。
- 管理会话与配对码周期独立，普通密钥替换撤销对应旧管理会话；房主通过 MANAGE 入房无需配对码。
- 在线以房间内用户的有效连接判定，直播收听者不计入。多标签页退出一个连接不能误判其他连接也退出。
- 最后连接离开后保留 10 秒缓冲；仍无人返回则暂停、停止该房间转码、断开全部直播连接。
- 再次有人进入保持暂停，只有显式播放操作恢复；前端和 Android 不得在 CONNECT 后自动取消暂停。
- 无用户期间直播请求不能恢复播放器或后台转码。

## 5. 持久化与实现边界

已采用以下文件分工：启动配置保存最高密钥、API 地址及默认参数；普通许可清单是统一持久化来源，手动编辑与网页操作维护同一清单；房间配置和数据保存至内嵌 SQLite，八项系统参数单独保存在 SQLite 的全局记录中。

房间归属使用稳定许可 ID，密钥字符串替换只变更密钥和会话版本，避免把密钥当数据库主键。手动替换应保留 ID；删除条目才触发房间级联删除。手动配置启动时验证重复 ID、重复密钥、格式与最高密钥冲突。

配置和数据库跨介质修改需要失败恢复记录或等效策略，确保删除/替换不会产生半完成状态。启动不能让旧清单覆盖管理台最新写入。

运行期每房间状态容器覆盖用户、播放、队列、聊天、投票、私人 FM/DJ、Cookie、直播。异步任务明确携带 roomId 和生命周期版本，不依赖请求线程里的隐式房间上下文。

WebSocket CONNECT/SEND/SUBSCRIBE 均鉴权。公开房间通过直接入口取得服务端入房凭据，房间 ID 本身不替代凭据。搜索、媒体、管理与直播 HTTP 接口同样检查权限；可信代理及全局限流统一处理。原配对码展示状态 `pairingOpen` 与房间开放状态 `publicRoom` 独立持久化，升级数据库保留旧 SHOW 状态并将已有房间设为 private。

默认房间缓存按房间隔离；资源调度器统一限制下载/转码并公平安排。只有确认音频来源、权限和质量一致后才考虑跨房间缓存共享。

管理会话默认有效 12 小时，可通过 `app.rooms.management-session-hours` 配置，不与配对码周期绑定，服务重启后重新验证管理许可。
