# 一起看视频 VT-00 实验记录

记录日期：2026-10-04。目标分支：`video-party`。规格：P0-spec v2。

**状态：尚未通过完整 VT-00 门槛。** 当前结果证明本机服务器网络能够返回符合 P0 形状的视频元数据和直链；它没有证明浏览器、双网络、HTTPS 部署或真实手机上的视频播放。软件中的既有音频兜底不作为本次视频验收证据。

## 已做的真实实验

从当前 Windows 主机向 Bilibili 请求普通公开视频的 `/x/web-interface/view` 与 `/x/player/playurl`。本次独立实验没有使用登录 Cookie，不代表应用支持匿名点播；最终应用要求房间配置 Cookie。媒体字节没有经过服务器，没有下载、缓存、代理或 FFmpeg 操作。

取流固定参数为 `bvid`、第一 P 的 `cid`、`fnval=1`、`platform=html5`、`qn=32`。没有添加 `try_look` 或 `high_quality`。API 请求的 Referer 为该 BV 的 Bilibili 视频页面；这是服务器元数据请求的 Referer，不能作为浏览器媒体请求采用 no-referrer 的证据。

第一 P 时长和流长度差异均小于 1 秒；播放器采用规格建议的 `max(2秒, min(0.5% × 时长, 10秒))` 容差。多 P 示例的聚合时长远大于第一 P 时长，所以实现只用 `pages[0].duration` 判断视频上限。

后两次探针明确观察到 HTTPS CDN URL 包含 `deadline` 字段。未记录 Cookie、完整 URL、签名参数值或响应正文。没有等待 URL 自然失效，不据此宣称固定有效期。

最初沙箱请求在连接本机代理 `127.0.0.1:7890` 时受到系统权限限制，没有获得 HTTP 响应；经只读网络探针权限后成功取得上表结果。该最初失败不属于 Bilibili 返回的 412。

## 按实测调整的适配细节

固定 P0 参数在多 P 示例返回 `format=mp4480`，单 P 返回 `format=mp4`。这两个值都是本实验观察到的 MP4 类型标签；适配器接受这两个明确值，保留实际标签和实际 quality，不接受未知 `mp4…` 前缀。该调整没有改变请求参数、第一 P 范围或引入多画质选择。

允许的媒体主机限定在 HTTPS `*.bilivideo.com` DNS 命名空间；当前实际观察到上表两台主机。不能据此宣称该命名空间中的每台 CDN 已经完成终端播放测试。新的 CDN 域名家族应先实验再维护允许列表。任意用户提供的 CDN URL、HTTP URL、伪装后缀、userinfo 和自定义端口均拒绝。

## 自动化验证与实测的区别

新增的 API 单元测试检查第一 P 输入规则、pages 可信元数据、视频时长、完整单段和时长一致性、试播 / DRM / DASH 拒绝、HTTPS CDN 约束、固定参数、错误类别和 deadline 解析。

新增的引擎测试使用受控 Mono / Sinks 和可注入时钟，验证暂停入队、首次起播、失败保留 pending、切模式取消旧解析、quota、clear 后不复活、刷新 singleflight 和进度 / 实例保留、Cookie 更新隔离、单调时钟、历史来源和批量逐项元数据验证。这些是模拟测试，不能替代真实 CDN 播放。

实际测试通过情况以本次最终测试报告为准；本文不预先声明整个项目测试已经通过。
